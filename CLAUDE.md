# Rivalift — guide for Claude Code

iOS gym log with weekly friend leagues. The product spec is `docs/PRD.md`; requirement IDs
(LOG-08, SOC-05, …) are the shared vocabulary for tasks and commits.

## Stack

- Swift 6, SwiftUI, Observation (`@Observable`), SwiftData (CloudKit private DB), Swift Charts
- iOS 17+, iPhone only
- Supabase backend from M4 (`supabase/`), not wired up yet
- Tests: Swift Testing (`RivaliftTests`), XCTest UI tests (`RivaliftUITests`)
- Project file is generated by XcodeGen from `project.yml`; `*.xcodeproj` is git-ignored

## Commands

```sh
brew install xcodegen          # once
xcodegen generate              # after adding/removing files or editing project.yml

# Build
xcodebuild -project Rivalift.xcodeproj -scheme Rivalift \
  -destination 'platform=iOS Simulator,name=iPhone 16' build

# Unit + UI tests
xcodebuild -project Rivalift.xcodeproj -scheme Rivalift \
  -destination 'platform=iOS Simulator,name=iPhone 16' test

# Unit tests only
xcodebuild ... test -only-testing:RivaliftTests

# Regenerate shared scoring vectors after changing scoring rules
python3 scripts/scoring_reference.py
```

Launch argument `-ui-testing` starts the app with an in-memory store (fresh onboarding).
The iPhone 16 simulator may not exist on newer Xcode; any iPhone simulator works.

## Layout

```
Rivalift/
  App/            RivaliftApp, RootView (tab bar + mini workout bar), AppEnvironment (DI)
  Core/
    Models/       SwiftData @Model types + versioned schema (RivaliftSchemaV1)
    Domain/       Pure logic, no SwiftData/UI: UnitConverter, OneRepMax, PRCalculator,
                  ProgressionEngine, LeagueScoreEstimator, StrengthScorer,
                  CustomCategoryScorer, WeekCalendar, SetValidator
    Data/         Repositories, SeedLoader, CSVExporter, SyncService (stub until M4)
    Services/     RestTimerService, NotificationService, Haptics
    DesignSystem/ Theme, shared components
  Features/       One folder per screen group; stores live next to their views
  Resources/      exercises.json, templates.json, Localizable.xcstrings, Assets
RivaliftTests/    Domain tests, scoring vector tests, repository integration tests
RivaliftUITests/  Main flows
scripts/          scoring_reference.py (reference scoring → Fixtures/scoring_vectors.json)
supabase/         migrations/, functions/ (M4+)
```

## Conventions

- Views never touch SwiftData or the network directly. They call stores
  (`WorkoutStore`) or repositories through `AppEnvironment`.
- Domain code works on value types (`SetSample`, `ExerciseBests`) and must stay free of
  SwiftData/SwiftUI so it can be unit-tested. Write tests for Domain before wiring UI.
- All weights are stored in **kilograms**. Convert only for display/input
  (`UnitConverter`, `WeightFormatter`). Compare weights with `WeightTolerance` (0.05 kg).
- CloudKit rules for every `@Model`: all attributes have defaults or are optional, all
  relationships are optional with an inverse, no `@Attribute(.unique)`. Enforce uniqueness
  in code (see `SeedLoader`, `SettingsRepository`). Store enums as raw strings (`…Raw`).
- Schema changes: add `RivaliftSchemaV2` and a migration stage; never edit V1 in place
  once shipped.
- Built-in exercises are identified by `key` (stable slug), never by name.
- Every mutation of the active session saves immediately (force-quit safety, LOG-13).
- Client-generated UUIDs for sessions so server upserts are idempotent.
- The server is the source of truth for league scores; the app only estimates. Any
  scoring change must update `scripts/scoring_reference.py`, the Swift scorer and (M5)
  the SQL, and all must pass `scoring_vectors.json`.
- User-facing strings are English and go through `LocalizedStringKey` /
  `String(localized:)` so they land in the String Catalog.
- Accessibility: 44×44 pt tap targets, VoiceOver labels on icon buttons, Dynamic Type
  (the set table switches to a stacked layout at accessibility sizes).
